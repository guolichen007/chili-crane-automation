## BENCH_ONLY 的 0.2 秒 freshness

owner 的 30 秒 DIFOP 到达观测：P50=20ms、P99≈33ms、max≈42ms。
observer 以 10Hz 发布，原 0.1 秒 TTL 导致 readiness 间歇 false；0.2 秒后稳定。
本轮仅在台架配置记录该值与来源，不冻结生产超时，不修改解析器或时间算法。

## 异常与运维边界

owner 在重启 pipeline 时发现 ptp4l：TX timestamp polling timeout → send sync failed →
MASTER → FAULTY，雷达临时 mode=0/status=2。owner 重启并使用
`tx_timestamp_timeout=100` 后恢复 mode=2/status=1/frame=1；这是现场执行事实，
不是本轮修改系统服务的授权。后续采集必须持续看 runtime status，不能靠启动记录放行。
若复发，停止采集并由部署 owner 检查 NIC/驱动/PHC/ptp4l。

AF_PACKET observer 需要 CAP_NET_RAW。owner 报告给通用 python3.10 setcap 后触发
secure-exec，LD_LIBRARY_PATH 丢失并破坏 ROS 库加载，已撤销；当时以 sudo 运行整条 pipeline。
**不把这一临时 workaround 当生产推荐**：后续由部署 owner 做 observer 最小权限隔离，
明确 source ROS/主仓库/vendor 环境；本轮不授予权限、不安装服务、不改 PTP。
